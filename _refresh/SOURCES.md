# Dashboard data sources and how to refresh them

Every number in the dashboard is embedded in the HTML as a single-line JSON literal
(`const ZD = [...];`, `const CHD = {...};` …). A "refresh" means: find the newest export
for a dataset, re-extract it to JSON, and swap that literal in **all four variants**.

```
python _refresh/refresh.py status          # what is stale, and where the newest export is
python _refresh/refresh.py status --deep   # regenerate every mismatching payload; report only the ones that really differ
python _refresh/refresh.py run             # re-extract stale sources + swap + stamp + version note
python _refresh/refresh.py run --dry-run   # same, but write nothing
python _refresh/refresh.py publish         # commit + push + verify the Pages build
python _refresh/refresh.py run --publish   # both in one go
```

Run from anywhere; paths are absolute. Python 3.12 + `openpyxl` is the only dependency.

### Why `status` rarely says STALE outright

Staleness is judged by comparing the newest discovered file's id with the id recorded at the last
apply, and that comparison is wrong in two everyday situations: a year-to-date export can never feed
the monthly archive datasets (`epm` / `epim`), and a dataset injected through
`refresh.py inject` records `_refresh/out/<const>.json` rather than the export behind it, so its id
never matches anything in Downloads. Both look permanently stale. `status` therefore says
`NEWER FILE THAN LAST APPLY` and only `status --deep` - which regenerates the payload into a
throwaway file and diffs it against the embedded literal - is allowed to call something
`STALE - payload would change`. A dataset whose apply timestamp is at or after the newest export is
reported as `up to date (applied after this export)` without extracting anything.

## The four variants

| file | role |
| --- | --- |
| `index.html` | live site (GitHub Pages source, `VSHOWN=false`) |
| `preview.html` | byte-identical copy of `index.html` |
| `public/index.html` | byte-identical copy (sanitised build) |
| `Zero_Dose_Digitization_Dashboard.html` | internal copy, `VSHOWN=true` (validator names visible) |

The first three must stay md5-identical; `refresh.py` asserts that before writing and
refuses to write anything unless every variant passed its asserts. Line endings stay CRLF.

Structural edits (markup, CSS, a render function) are hand-written once into `index.html`, then
`python _refresh/push_master.py --dry-run` and `push_master.py` copy the master to `preview.html`
and `public/index.html` and regenerate the internal build from the new master plus the internal
file's own `VCH` / `AFP` / `WPV` payloads and `VSHOWN = true`. Before writing anything the tool
proves that the same regeneration still reproduces the *current* internal build from the previous
copy byte for byte, so a per-variant difference outside those four regions cannot be flattened away
by an overwrite. It then bumps the PKT stamp in all four files, appends the version.txt note and
records the push under `state.json → last_push`. Payload-only changes go through
`refresh.py run` / `refresh.py inject` instead, which swap a single `const` literal in all four.

## What `run` guarantees

* **Two-phase**: every variant is mutated in memory; nothing is written until all asserts
  pass (payload parses as JSON, `const X` appears exactly once, all line endings CRLF,
  the identical group still matches).
* **Size guard**: a payload that would shrink below 20 % or grow past 500 % of its current
  size aborts the run (catches truncated or empty exports). `--force` overrides.
* **No-op detection**: if the regenerated JSON is byte-identical to what is embedded,
  nothing is written and the timestamps are left alone (`NO_CHANGE`).
* **Stamps**: the hero `Updated …` chip and, when the variant carries one, the header
  `Last updated …` stamp are set to the current PKT time, and one line is appended to
  `version.txt` and `public/version.txt`. `--no-stamp` skips both. Only a prefixed
  occurrence moves, because the extractors write their own build time (`gen`) into the
  payloads in the same format - a blind replace re-dated datasets the run never touched.
* **Provenance**: `_refresh/state.json` records, per dataset, the source path/mtime/size,
  the payload SHA-1, its char count, the summary line and the stamp applied. `status`
  compares against it to decide what is stale.
* **Publish** is opt-in (`--publish` or the separate `publish` command). It stages only the
  four variants, the two version files and `_refresh/state.json`, pushes, then polls
  `/pages/builds/latest` and compares the live `content-length` with the local file
  (raw or LF-normalised - the huge HTML blobs are stored byte-for-byte and keep CRLF
  even with `autocrlf`). The GitHub token comes from
  `git credential fill`, is piped into curl over stdin, and is never printed.
* **Publish carries only its own work.** The staged-files rule is not enough: the variant
  HTML *is* this route's output, so a feature edit and a payload swap land in the same file
  and a path allowlist cannot tell them apart. So before staging, `publish` diffs every
  variant against `HEAD` line by line, both added and removed, and refuses (exit 3, nothing
  staged, files left on disk) unless each changed line is one of the payload `const …`
  declarations listed in `sources.json` or carries a visible `Updated …` stamp chip. The
  26-Oct-2026 scheduled NEAP run is what this catches: it committed 310 added lines into all
  four variants, 4 of them payload consts and 1 the stamp, the other 305 an unfinished PTP
  feature published under a data-refresh message. `--allow-pending` says you mean it and names
  the count; use it when the pending work is deliberate and already reviewed. The guard only
  runs when a variant is actually dirty, and a publish with nothing of its own to commit says
  so instead of trying an empty commit.

## Adding a dataset

1. Add an entry to `sources.json` (`auto` with an `extractor`, or `manual` with a `howto`).
2. Write `_refresh/extract_<id>.py`: discover the source with `srcutil.newest(cfg['auto'][id])`,
   build the object, write `srcutil.dumps(obj)` to `--out`, print
   `SRC <id> <path>` and `OK <id> <chars> <summary>`.
3. `python _refresh/refresh.py run --only <id> --force --dry-run` - the payload should come
   back byte-identical if nothing in the source changed. That is the faithfulness test.
